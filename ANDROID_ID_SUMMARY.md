# Android ID Generation - Executive Summary

## Quick Answer

### How is the ID generated on first Android installation?

RustDesk generates a **unique Device ID** using:
- **UUID v4** (random) generated by `Uuid::new_v4()`
- Base64 encoded and persisted to app configuration
- Stored in `/data/data/com.carriez.flutter_hbb/shared_prefs/`

### Is the same ID generated after every installation?

**NO** ❌

- **After app reinstall:** New ID is generated (app data is deleted)
- **After reboot/restart:** Same ID (config is preserved)
- **After factory reset:** New ID

## Key Findings

### What Happens During Different Scenarios

| Scenario | ID Behavior | Reason |
|----------|---|---|
| **Fresh Installation** | Generate new ID | First time running app |
| **App Restart** | Same ID ✅ | Config file still exists |
| **App Uninstall + Reinstall** | Different ID ❌ | `/data/data/` directory deleted |
| **Clear App Data** | Different ID ❌ | Config files deleted |
| **Device Reboot** | Same ID ✅ | Storage preserved |
| **Factory Reset** | Different ID ❌ | Entire device wiped |

### Code Path on First Launch

```
App Launch → Flutter → Rust FFI → UUID::new_v4() → Base64 → SharedPreferences
                      ↓
                Config::get_id()
                      ↓
                /data/data/com.carriez.flutter_hbb/shared_prefs/
```

## Technical Details

### ID Types

1. **Device ID (Peer ID)**
   - Purpose: Identify the device in the network
   - Format: Base64-encoded string
   - Generated: Once per first launch
   - Persistence: Until app data cleared

2. **UUID (Session ID)**
   - Purpose: Session and relay identification
   - Format: Base64-encoded UUID v4
   - Generated: Every session/restart
   - Persistence: Session only

### Storage Location

```
Android Private App Data:
/data/data/com.carriez.flutter_hbb/
├── shared_prefs/
│   └── KEY_SHARED_PREFERENCES (contains UUID and app config)
└── files/
    └── config/ (Rust configuration files)
```

## Solutions to Keep Same ID After Reinstall

### 3 Implementation Options

#### Option 1: Android Backup Service ⭐ RECOMMENDED
- **Complexity:** Low (40 lines of code)
- **How:** Android automatically backs up and restores app data
- **Pros:** No server needed, user-controlled
- **Implementation:** Add `BackupAgentHelper` to manifest + Kotlin class

#### Option 2: Cloud Sync
- **Complexity:** High (200+ lines of code)
- **How:** Manually backup ID to server on first install, restore on reinstall
- **Pros:** Full control, independent of Android backup
- **Implementation:** Rust backend + Flutter frontend code

#### Option 3: Hardware-Based ID
- **Complexity:** Medium (100+ lines of code)
- **How:** Derive ID from device hardware (ANDROID_ID, serial, etc.)
- **Pros:** Survives reinstalls naturally, no server needed
- **Implementation:** Kotlin utility + Rust integration

## Security Note

Generated IDs use `Uuid::new_v4()` which is:
- ✅ Cryptographically random
- ✅ Not guessable (2^128 possibilities)
- ✅ Stored in app-private directory
- ⚙️ Exposed over network (standard for RDP/RTC)

No special security concerns unique to this implementation.
